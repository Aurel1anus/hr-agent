# HR 招聘并发管理系统 MVP 前端功能清单

## 1. 当前产品范围

当前版本只解决：

> 多岗位、多候选人并发招聘过程中的流程记录、进度管理、待办管理和防遗漏。

技术栈：

```text
Frontend
React
TypeScript
Tailwind CSS
shadcn/ui

Backend
FastAPI
SQLAlchemy
PostgreSQL / SQLite
```

当前版本不包含：

```text
LLM
AI筛简历
AI聊天
RAG
Boss自动操作
北森自动操作
钉钉自动操作
自动发Offer
```

所有操作均由 HR 手动完成。

---

# 2. 整体页面结构

左侧固定导航：

```text
招聘助手

📊 工作台
💼 招聘岗位
👥 全部候选人
✅ 待办事项

────────────

当前用户
```

MVP 共四个主要页面：

```text
1. 工作台 Dashboard
2. 招聘岗位 Jobs
3. 全部候选人 Candidates
4. 待办事项 Tasks
```

另外存在两个重要的非独立页面组件：

```text
岗位详情页
候选人详情 Drawer
```

# 51. Loading 状态

所有 API 请求都必须有 Loading。

例如：

```text
正在加载岗位...

正在保存...

正在更新候选人...
```

按钮提交时禁用。

避免用户连续点击。

---

# 52. 错误提示

请求失败：

```text
更新失败，请重试。
```

不要静默失败。

例如：

```text
面试时间保存失败。
```

使用 Toast 提示。

---

# 53. 成功提示

重要操作成功：

```text
候选人已添加

招聘阶段已更新

待办已完成

面试已创建
```

使用 Toast。

不要每一个小操作都弹 Modal。


# 55. 页面刷新

刷新浏览器后：

```text
当前数据必须保持
```

因为状态全部保存在后端数据库。

React State 只负责：

```text
UI 临时状态
```

不能作为招聘流程真实数据来源。

```text
招聘岗位

新建岗位
↓
填写岗位信息

创建

进入岗位 Kanban
```

```text
岗位
↓
添加候选人
↓
填写基本信息
↓
进入待筛选
```

```text
打开候选人
↓
查看状态
↓
完成当前工作
↓
改变阶段
↓
创建下一步 Task
```

```text
询问候选人问题

正在等待候选人
```

```text
发送简历给面试官

设置：
正在等待面试官

创建：
明天10点跟进
```

```text
约面中
↓
确认双方时间

创建 Interview

进入待面试
```

```text
待面试
↓
面试完成
↓
待面评
↓
面评完成
↓
待结果
```

```text
待结果
↓
Offer
```

或者：

```text
待结果

淘汰
```

# 61. 当前 MVP 的真正核心功能

虽然上面有很多 UI 功能，但真正核心只有：

```text
岗位隔离
+
候选人 Pipeline
+
Blocked By
+
Task
+
Interview
+
Activity Timeline
```

也就是任何时候系统都可以回答：

```text
这个候选人属于哪个岗位？

现在走到哪一步？

现在卡在谁？

下一步要干什么？

什么时候处理？

过去发生过什么？
```

只要这六个问题能稳定回答，这个 MVP 就已经具备实际使用价值。
